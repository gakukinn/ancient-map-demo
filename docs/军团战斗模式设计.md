# 军团战斗模式设计：野战 vs 攻城

关于您的问题：“野战需要和攻城战分开吗？”

**简短回答：底层逻辑合并，但游戏规则（Rules of Engagement）必须分开。**

基于对 `CombatSystem` 和 `MultiLegionFieldBattle` 的代码分析，目前的系统有“混用”的迹象。为了达到您想要的“战略深度”（类似信长之野望），我们不能让野战仅仅是“没有城墙的攻城战”。

以下是基于数据分析的综合设计建议：

## 1. 核心架构：统一引擎 (Unified Engine)

虽然规则不同，但底层代码应统一使用现有的 **`BattleField` (区域战斗系统)**。
不要维护两套独立的 `startBattle` (1v1) 和 `startSiege`。所有的战斗本质上都是“多对多”的实体交互。

- **优势**：
  - 援军系统可以通用。无论是野战还是攻城，援军到达逻辑一致。
  - 兵力计算、DPS公式通用。
  - 视觉效果（特效管理）统一。

---

## 2. 差异化设计 (The Differences)

为了避免“单调”，野战和攻城战必须提供截然不同的**战术体验**。

| 维度 | **野战 (Field Battle)** | **攻城战 (Siege Battle)** |
| :--- | :--- | :--- |
| **核心体验** | **"机动与包围" (Maneuver)** | **"坚守与突破" (Attrition)** |
| **胜利条件** | 击溃敌军士气（Rout）或全歼 | 占领城市核心（Capture） |
| **地形影响** | **决定性 (Critical)**<br>骑兵在平原 +20%，山地 -30% | **固定 (Static)**<br>守方恒定 +50% 防御 (城防) |
| **阵型规则** | **开放战场**<br>支持多方向夹击 (Flanking Bonus) | **阻塞战场 (Choke Point)**<br>有“投入上限” (无法所有兵力一拥而上) |
| **特殊机制** | **遭遇战 (Encounter)**<br>双方同时持续移动，可能发生“追击” | **攻坚阶段 (Stages)**<br>先登 -> 陷阵 -> 斩将 -> 夺旗 |

### 2.1 野战模式详解 (Field Battle Mode)

**"狭路相逢勇者胜，智者胜于未战。"**

*   **夹击系统 (Flanking)**:
    *   在野战中，位置就是一切。
    *   规则：每增加一个攻击角度（如一支军团从后方 `BATTLE_OFFSET` 相反方向进入），敌军士气下降速度 **+50%**。
    *   **玩家操作**：不仅仅是点“攻击”，而是先派一支部队正面牵制，操作主力绕道后方。

*   **地形利用**:
    *   代码中已有 `TerrainSpeedSystem`。
    *   规则：在此基础上，引入战斗修正。
    *   `if (hex.type === MOUNTAIN && unit.type === CAVALRY) damage *= 0.7;`

### 2.2 攻城模式详解 (Siege Mode)

**"上兵伐谋，其次伐交，其次伐兵，其下攻城。"**

*   **城防体系**:
    *   城市不仅仅是血量多的单位。
    *   规则：城市拥有 `WallStrength` (城防)。在城防归零前，驻军受到的伤害 **减少 80%**。
    *   **攻方策略**：必须先派“攻城兵” (Infantry) 消耗城防，或者用“计略”降低城防，否则骑兵撞墙就是送死。

*   **围点打援**:
    *   这是数据分析中发现的现有系统亮点（`triggerDefensiveReinforcements`）。
    *   攻城的精髓往往不在攻城本身，而在**消灭来救的援军**。应该强化这一点，让攻城变成诱饵。

---

## 3. 实施建议 (Implementation Path)

基于现在的代码，我们可以通过**“配置驱动”**的方式来实现这种分离，而不需要重写核心。

### 步骤 1：标准化 BattleField
修改 `MultiLegionFieldBattle`，使其不仅处理“位置”，还根据战斗类型传递不同的 `BattleConfig`。

```typescript
// 伪代码：战斗配置对象
interface BattleRules {
  canFlank: boolean;       // 野战=true, 攻城=false
  defenseBonus: number;    // 野战=1.0, 攻城=1.5
  retreatThreshold: number;// 野战=士气0/兵力10%, 攻城=死战到底
}
```

### 步骤 2：激活野战的“夹击”数据
利用现有的坐标数据，计算夹角。如果发现两支友军对同一敌军的夹角 > 90度，触发 `Flanking` 状态（UI显示“夹击！”），给予巨大的 DPS 奖励。

## 4. 画面感优化：六边形战术可视化 (Visual Arts on Hex Map)

您提到大地图是六边形组成的，目前的战斗视觉仅是“两个点在特效中震动”，缺乏棋盘游戏的**“占位感”和“博弈感”**。

建议引入以下视觉元素，让玩家一眼看懂战局：

### 4.1 战术格高亮 (Tactical Hex Highlight)
*   **当前问题**：战斗看似发生在两点连线上，忽略了地块本身。
*   **优化方案**：
    *   **占领格**：战斗时，攻守双方所在的六边形底色高亮（攻方红色脉冲，守方蓝色坚盾）。
    *   **交战线 (The Front)**：在两个六边形的交界边，绘制激烈的**刀光特效**，而不是在空中乱飞。
    *   **ZOC (控制区)**：战斗周围的一圈六边形变暗，标示为“战区 (War Zone)”，玩家直观感受到“这里路不通”。

### 4.2 夹击可视化 (Flanking Indicators)
*   **当前问题**：多军团混战时，只看到一堆人挤在一起。
*   **优化方案**：
    *   **攻击矢量**：从每一个攻击军团的六边形中心，绘制一条指向防守军团的**动态箭头**。
    *   **致命角度**：当达成 `Flanking` 条件（>90度夹角）时，该箭头变为**金黄色**并带有粒子特效，提示玩家“这是致命一击”。

### 4.3 兵力可视化 (Troop Density)
*   **当前问题**：1万兵和10万兵看起来差不多（只是方阵人数略有不同）。
*   **优化方案**：
    *   **六边形填满度**：根据兵力/地块上限，在六边形内部绘制**“兵力浓度”**填充（类似《文明》系列的单位堆叠感，或者类似《钢铁雄心》的兵牌厚度）。

---

## 5. 总结
**是，必须分开。**
不是在代码上写两套系统，而是在**规则层**赋予它们不同的灵魂。
- **野战玩的是“线”**（机动、切断、包围）。
- **攻城玩的是“点”**（突破、消耗、时机）。

**加上六边形的视觉优化，您的游戏将从“数值对撞”进化为真正的“地图博弈”。**
