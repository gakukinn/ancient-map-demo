# 沙盒模拟器规划 (Sandbox Simulator Plan)

## 1. 核心定位 (Core Identity)
*   **游戏类型**: 2D 世界地形模拟 (World Terrain Map).
*   **视觉风格**: 类似《文明》的 2D 策略风格 (Civ-like).

## 2. 技术可行性分析 (Technical Feasibility)

### A. 全球地图现状 (Current Map Status)
*   **已解锁**: 经代码核查，`GameMap.ts` 虽然引用了边界配置，但**并未将 `maxBounds` 应用于地图实例**。
*   **结论**: 现在的地图实际上已经是**全球无缝滚动**的。无需进行任何解锁操作。

### B. 性能策略 (Performance Strategy)
*   **保持现状**: 沿用现有 2D 渲染，不做 10万单位的 GPU 升级，优先保证逻辑开发。

### C. 服务器架构 (Sync Architecture)
*   **挑战**: 只有一台服务器，如何让全球观众同步？
*   **解决**:
    *   **"伪直播" (Pseudo-Live)**: 服务器不传输实时帧，只传输 **"指令序列 (Command Logs)"**。
    *   **客户端计算**: 用户的电脑接收指令（如 `Time:100, Unit_A move to (x,y)`），然后在本地重现画面。
    *   **优势**: 极大降低带宽成本。一台 $5/月的 VPS 即可支撑。

### D. 结论
**完全可行**。
核心难点在于前端渲染优化（GPU Instancing），而非后端。建议使用 `Pixi.js` + `Data Texture` 技术栈。
